**Спеціальність:** F2 «Інженерія програмного забезпечення»

**Виконавець:** Залога Нікіта Іванович

## Матриця нефункціональних вимог (NFRs)

Таблиця-резюме вимог, повний варіант яких наведено в підрозділі 1.5.3 (таблиця 1.2).

| № | Категорія | Метрика / індикатор |
|---|---|---|
| NFR-1 | Продуктивність | `POST /messages`: p95 ≤ 200 мс, p99 ≤ 500 мс при 300 RPS |
| NFR-2 | Продуктивність | `GET /chats/{id}/messages`: p95 ≤ 150 мс при 500 RPS |
| NFR-3 | Продуктивність | Наскрізна доставка онлайн-отримувачу: p95 ≤ 300 мс |
| NFR-4 | Масштабованість | ≥ 5 000 WebSocket-з’єднань на екземпляр API, stateless-екземпляри за Nginx |
| NFR-5 | Продуктивність клієнта | Шифрування повідомлення p95 ≤ 10 мс; гранти для групи з 256 учасників ≤ 2 с |
| NFR-6 | Криптографія | AES-256-GCM, HKDF-SHA256, X25519, Ed25519; сервер зберігає лише шифротекст |
| NFR-7 | Транспорт | TLS 1.3, HSTS max-age = 31 536 000 с, оцінка SSL Labs не нижче A |
| NFR-8 | Автентифікація | JWT HS256 у HttpOnly-cookie (30 хв / 7 днів), bcrypt, Argon2id m ≥ 64 МіБ, t ≥ 3, p = 4 |
| NFR-9 | Стійкість до перебору | Rate limiting у Redis (fail-closed): OTP ≤ 5 спроб за 15 хв, ≤ 300 повідомлень/хв |
| NFR-10 | Комплаєнс | OWASP ASVS 5.0 L2, GDPR, журнал аудиту 365 днів |
| NFR-11 | Надійність доставки | At-least-once із серверною дедуплікацією, 0 втрат при розриві з’єднання на 5 хв |
| NFR-12 | Інфраструктура | 9 контейнерів Docker Compose з healthcheck, доступність ≥ 99,5 % на місяць |
| NFR-13 | Резервне копіювання | Щоденні pg_dump і mongodump, RPO ≤ 24 год, RTO ≤ 1 год |
| NFR-14 | Якість коду | ≥ 329 інтеграційних тестів у CI, покриття коду серверної частини ≥ 80 % рядків |
