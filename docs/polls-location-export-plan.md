# План: опитування, геолокація та експорт історії чату

Одна гілка, один Pull Request. Рішення власника (01.11.2026): опитування публічні й
анонімні; геолокація як картка з координатами та посиланням; експорт лише в JSON.

## 1. Опитування (polls)

Сервер не бачить ні питання, ні варіантів, ні голосів: усе це корисне навантаження
зашифрованого повідомлення (формат у `docs/crypto-spec-v1.md`). Підрахунок виконує клієнт.

- **Створення.** Звичайне зашифроване повідомлення з типом `poll`: питання, 2 до 10
  варіантів, `multiple` (кілька відповідей), `anonymous`, необов'язковий `closes_at`.
  Створювати можна в приватних і групових чатах (у каналах ні: пости каналу підписані та
  не шифруються).
- **Голос і закриття** надсилаються як керувальні повідомлення (`is_control = true`) з
  видимим серверу полем `poll_message_id` (метадані: яке опитування, без вмісту). Нова
  відповідь того самого користувача замінює попередню (за порядком `ObjectId`). Закрити може
  лише автор опитування; голоси після закриття ігноруються клієнтом.
- **Що робить сервер.** Керувальні повідомлення не збільшують лічильник непрочитаних і не
  стають `last_message`; у звичайній стрічці історії не повертаються. Їх можна отримати
  окремим запитом за опитуванням. Решта перевірок (членство, епоха, підпис, ліміти) діє як
  для будь-якого повідомлення.
- **Анонімність: чесна межа.** Кожне повідомлення підписане ключем відправника, тож
  криптографічно голос завжди пов'язаний з акаунтом. Режим `anonymous` приховує, хто за що
  проголосував, лише в інтерфейсі: учасник зі зміненим клієнтом цю інформацію отримає.
  Справжня анонімність потребує сліпих підписів або кілець підписів і каналу без прив'язки
  до відправника, чого цей застосунок не має. Інтерфейс і документація мусять так і казати.

## 2. Геолокація

- Клієнт бере координати через `navigator.geolocation` лише після явної дії користувача
  (дозвіл браузера), показує попередній перегляд і надсилає зашифроване повідомлення типу
  `location` (широта, довгота, точність, необов'язкова підпис). Живу геолокацію не
  підтримуємо.
- Відображення: картка з координатами та кнопкою «Відкрити на карті» (посилання на
  OpenStreetMap у новій вкладці, `rel="noopener noreferrer"`). Жодних запитів до сторонніх
  тайлів, CSP не змінюється. Координати перевіряються (діапазон, число) перед показом.
- Серверних змін немає.

## 3. Експорт історії чату

- Лише клієнт: розшифровує історію локально, збирає JSON і віддає файл (`Blob`). Сервер
  отримує звичайні запити історії.
- Вміст: метадані чату, учасники (імена на момент експорту), повідомлення з часом,
  відправником, відповідями, пересиланнями, реакціями, опитуваннями (запитання, варіанти,
  підсумки; у анонімних лише підсумки), геолокаціями, для вкладень лише ім'я, тип і
  розмір. Повідомлення, які не вдалося розшифрувати, потрапляють зі станом
  (`no_key`, `failed` тощо), а не пропускаються мовчки.
- Інтерфейс: пункт у інформації про чат, індикатор прогресу та скасування. У файлі немає
  ключів; користувач попереджається, що файл містить розшифрований вміст.

## 4. Порядок виконання

1. Серверна частина (керувальні повідомлення, запит голосів, тести).
2. Клієнт: формат корисного навантаження, опитування, геолокація, експорт, специфікації.
3. Огляд коду та безпековий огляд, виправлення.
4. Документація: `docs/crypto-spec-v1.md`, `docs/ui-states.md`, `docs/tech-debt.md`.

## 5. Обмеження

Коміти без співавторів та підписів Claude; `CLAUDE.md` і `.claude/` не комітяться;
після змін криптографічного шару `npm run interop`; інтеграційні тести з увімкненим rate
limiting.
