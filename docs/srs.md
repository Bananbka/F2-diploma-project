# Специфікація вимог до програмного забезпечення (SRS)

> Документ відповідає структурі ISO/IEC/IEEE 29148:2018. Вимоги отримано з моделі To-Be [Розділу 1](1_analysis.md) (функції F1–F8, вимоги NFR-1 – NFR-14) і розширено за результатами аудиту. Архітектурну реалізацію вимог наведено в [Розділі 2](2_design.md), обґрунтування ключового рішення – в [ADR-001](adr/0001-choice-of-technology.md).

## 1. System Context (Контекст системи)

### 1.1 Призначення і межі

Система призначена для обміну повідомленнями та файлами в особистих чатах, групах і каналах з наскрізним шифруванням. До меж системи належать:

- клієнтський застосунок (Angular SPA), що виконує всі криптографічні операції з відкритим вмістом і ключами;
- серверний контур: шлюз Nginx, API FastAPI з WebSocket, фонові обробники Celery, сховища PostgreSQL, MongoDB, Redis і RustFS.

Серверний контур виконує автентифікацію, маршрутизацію й зберігання шифротекстів і координацію епох ключів. Доступу до відкритого вмісту повідомлень і вкладень серверний контур не має.

Поза межами системи: нативні мобільні клієнти, голосові та відеодзвінки, федерація з іншими месенджерами.

### 1.2 Актори і зовнішні системи

| Актор / система | Тип | Взаємодія із системою |
|---|---|---|
| Користувач | Person | Реєстрація, вхід, обмін повідомленнями через браузер |
| Власник / адміністратор чату | Person | Керування складом групи, публікація в каналах |
| SMTP-сервер | Зовнішня система | Доставка листів з одноразовими кодами (SMTP / STARTTLS, порт 587) |

### 1.3 Обмеження та припущення

- **Модель загроз:** сервер розглядається як «чесний, але цікавий» учасник. Метадані (склад груп, час, розміри повідомлень) серверу доступні.
- **Розгортання:** один вузол, Docker Compose. Керовані хмарні сервіси не використовуються.
- **Середовище клієнта:** браузер із підтримкою Web Crypto API (X25519, Ed25519, AES-GCM, HKDF).
- **Криптографічна схема:** sender-key ratchet з епохами відповідно до [ADR-001](adr/0001-choice-of-technology.md) і нормативної специфікації [crypto-spec-v1.md](crypto-spec-v1.md).

## 5. Glossary (Глосарій)

| Термін | Визначення |
|---|---|
| E2EE (End-to-End Encryption) | Модель шифрування, за якої відкритий вміст доступний лише кінцевим пристроям учасників, а сервер передає й зберігає тільки шифротекст. |
| Sender-key ratchet | Схема групового шифрування, у якій кожен пристрій-відправник веде односпрямований KDF-ланцюжок (HKDF-SHA256) і виводить з нього окремий ключ для кожного повідомлення. |
| Епоха (epoch) | Серверний запис (`chat_id`, `epoch`, `member_set_hash`, `reason`), що визначає період дії групових ключів між двома змінами складу учасників. |
| Грант (grant) | Ланцюговий ключ відправника, зашифрований на X25519-ключ конкретного пристрою-отримувача. |
| `member_set_hash` | SHA-256 від відсортованого списку пристроїв учасників епохи; використовується клієнтом для перевірки складу групи. |
| Safety number | Числовий відбиток (60 цифр) ключів підпису двох співрозмовників для ручної перевірки відсутності підміни ключа. |
| JWT (JSON Web Token) | Підписаний токен доступу (RFC 7519), що передається в HttpOnly-cookie. |
| p95 Latency | Значення затримки, яке не перевищують 95 % запитів у вибірці вимірювання. |
| At-least-once | Гарантія доставки, за якої кожна подія доставляється щонайменше один раз, а дублікати усуваються на боці отримувача або сервера. |
